## 运行进程诊断

旧实例 PID 2372：Physical footprint 约 2.0 GB，Image IO 部分约 1.8 GB，普通堆分配约 100 MB。存活 81 个 CursorState、81 个 IIOImageRead、164 个本地事件观察对象。抽查历史 CGImage 由 CA::Render::image_cache 持有。leaks 检测约 643 KB 的监视器引用循环；该数值不涵盖所有图片缓存。

## 修改

- LocalEventMonitor 用引用对象管理令牌，重复注册先清旧令牌，析构清理；handler 弱引用独立光标状态及屏幕，避免捕获 SelectionView 和冻结帧。
- 截图、钉图、长图预览改为 NSView 直接绘制 CGImage，不把历史大图作为 SwiftUI Image 纹理留在 CA image_cache。
- 标注预览直接绘制，保留文字、路径、白色标注描边、模糊路径和标注覆盖顺序。模糊缓存仅服务当前选区和当前标注的半径，清理时释放。
- 截图窗口关闭时解除 first responder、释放图片与图层内容、拆 contentView 并 close；钉图清关闭回调，长图清 preview 和宿主视图。
- PNG 冻结帧转换为独立 bitmap，长期保留的小裁剪输出重绘为独立小 bitmap，保持颜色空间、像素尺寸与 alpha。
- ImageIO 直接编码 PNG/TIFF，保留两种剪贴板格式，去除 TIFF 中转解码。
- 长图在裁剪和创建 Task 前使用线程安全入口控制，整个处理链最多一帧在途，繁忙时丢帧；取消直接 discard，完成只创建一次快照、释放画布/参考帧/预览；流错误和启动失败统一清理。

钉图 + 打码真实窗口压力测试（1280×720 图片，反复改变模糊半径并关闭）：10/20/30/40/50/60 轮分别约 129.2/123.5/141.7/134.6/126.2/130.4 MiB，无线性增长。

真实窗口压力测试会反复覆盖桌面，用户报告外接显示器短暂花屏，可能由这些窗口/图层快速切换造成。已停止所有这类测试，所有测试进程均结束。没有修改显示器分辨率或刷新率。今后这些测试仅通过显式 KACHA_MEMORY_STRESS=1 开启，不在日常单测自动执行。
